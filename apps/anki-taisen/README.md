## 1. 構成

- `index.html`: ビルド済みの単一HTML（`src/pubhead.html` ＋ ビルド結果）。直接編集しない。
- `src/src.html`: 本体のソース（正本）。`src/build.py` が鳥・木・歴史の素材情報と学問の札を埋め込み、`index.html` と `data/` を作る。
- `data/<科目>.json`: 学問の札（選んだ科目だけ遅延読み込み）。`data/dx-history.json`・`dx-en.json` は用語辞典、`data/topics.json` は人生クエストのトピック → 札の枚数。

- アイコンはリポジトリ直下の `/shared/icons/`（人生クエストと共用、`shared/README.md`）。
- ビルドの入力のうち、学問の札の原稿（`concepts/*.json`、英語辞書 `dict-en.json`、資料画像 `concepts/img/`）と鳥の原稿（`birds.js`）は作業フォルダ（Claudeのプロジェクトファイル `mekuri-battle/`）にある。`src/` はビルドスクリプトと素材メタデータの控え。鳥・木の元画像や録音そのものは控えていないので、既存の `b/` `t/` を作り直すときは取り直しになる。

## 1.9 問題づくりのルール（2026-11-24 Keita「問題づくりルールもちゃんと策定しようや。意味のないクイズ作っても無駄だから」）
札を作る・直す前に必ずこれを読む。§2.0（検証）と §2.1（レベル感）より先に来る。

### 1.9.1 意味のある問題とは
「正解できるようになったら、その分野で何ができるようになるか」を1文で言える問題だけを作る。言えない問題は、どれだけ正確でも作らない。
- 良い例: 「鎌倉幕府が倒れたのはなぜ？」→ 恩賞と土地のしくみが分かり、他の政権の崩れ方にも使える。「暖色と寒色、部屋を広く見せたいのはどっち？」→ 部屋づくりで使える。
- 悪い例: 「〇〇区にある△△で知られるのは？」（名前を言えても何も分からない）、「□□を設計したのは誰？」（人名を覚えるだけ）、「××は何メートル？」（数字のための数字）。

### 1.9.2 問いの型（ジャンルを作るとき、どの型を使うか先に決めて README に書く）
1. なぜ？（原因・しくみ）: なぜそうなるか、なぜそこにあるか。歴史・地理・理科・経済の中心。
2. どうなる？（結果・予測）: これをするとどうなるか、何が変わったか。
3. どう違う？（見分け・使い分け）: 似たもの2つの違い、どちらを使う場面か（例: 如来と菩薩の見分け、尊敬語と謙譲語）。
4. どれを選ぶ？（場面での判断）: 状況を示して最適なものを選ぶ（例: 冠婚葬祭の服、料理に合うワイン）。
5. つながり: 時代・地域・分野をこえて同じ型を見つける。
6. 基本語彙: その分野を語るのに要る用語・名前を、意味から言えるか。**これだけで作らない。** 上の1〜5の問いを読むのに要る語に限る。

### 1.9.3 作らない問題
- 名前・人名・年・数字を当てるだけで、答えを知っても理解が増えないもの（基本語彙として 1.9.2 の6に当たるものは除く）。
- 「〜で知られる○○は？」のように、問題文が名所・作品の羅列で、答えの中身（何がすごいか・なぜ大事か）が問題にも解説にも出てこないもの。
- 一つの資料にしか出ない細部・ランキング・記録（「日本一○○な」だけが手がかりの問題）。時事問題で今月の背景を知るために要るものは除く。
- 知識がなくても字面・消去法で当たるもの、答えが問題文から読めるもの（§2.0 の leak・hint）。
- 解説が問題文の言い換えだけのもの。解説には「なるほど」となる理由・具体例・その後を書く。

### 1.9.4 作る手順
1. ジャンルの「ねらい」を README に1〜3行で書く（この分野で身につけたいこと。例: 東京地理＝地形・水・鉄道・江戸の町割りから、今の東京の姿を説明できる）。
2. ねらいに沿って、押さえるべき要点（本質）を10〜20個に絞って書き出す（資料に当たる）。
3. 要点ごとに 1.9.2 の型で問いを作る。基本語彙の札は、要点の問いを読むのに要る語だけ。目安として、基本語彙の札はジャンルの半分まで（歴史は 0、§2.0.5）。
4. 1枚ずつ「正解できたら何ができるか」を1文で言えるか確かめる。言えない札は捨てる。
5. 答え方を選ぶ: 一語で答えられる＝入力・4択、文で答える（なぜ・どうなる）＝採点（§2.0.5 の形式）。
6. §2.0 の検証（全部読む・関門・表示確認）を通す。

## 2.0 札の検証（2026-11-18 Keita「検証おこたるなよ。これからも作成時は検証しろよ？」）
札を作ったり直したりしたら、公開前に必ず次をすべて行う。
1. 出題文（d）を出題画面と同じ形で全部読む。誰が何をするかが伝わるか、答えが1つに決まるか（あらすじを詰めすぎない）。
2. 機械チェック: 答え（かっこ書きを除く）やその3文字以上の部分が d に入っていないか、答えが「AとB」「A・B・C」の組になっていないか（組は1枚ずつに分ける）。固有名の一部（師匠・親の名字など）が d に出ていないか。
3. 公開版（またはローカル）で実際に数枚遊んで表示を確かめる。
4. 生成元のスクリプトがあるジャンルは、直した文をスクリプト側にも反映する（再生成で戻らないように）。
- 2026-11-18 の見直し: 落語・お笑いの出題文を全部書き直し、全ジャンルで答えが出題文に出ていた約70枚を直し、2つ組の答え14組を1枚ずつに分けた（天王星／海王星、陽イオン／陰イオン、長調／短調、直列回路／並列回路、陽子／中性子、根／茎／葉、文化遺産／自然遺産 など）。whj.py（世界遺産（日本）の生成元）には「文化遺産と自然遺産」の組が残っているので、再生成したら分け直す。
### 2.0.1 札の関門（2026-11-18 Keita「最初に仕組みとしてslopができないようにしてなかったのが良くなかった」）
注意や規則ではなく仕組みで止める。AIは使わない（毎回トークンを食わない）。
- `python3 apps/anki-taisen/tools/check_cards.py`: data/*.json と index.html の資料画像を調べ、1件でも引っかかれば失敗。調べること＝leak（問題文に答え・別解・かっこ書き）、pair（AとB の2つ組）、reverse（問題文が短すぎる／答えの方が長い）、term（答えが文・長すぎ）、hint（答えと頭が同じ別の札の答えが問題文に出る。志ん朝に「志ん生」）、vague（同じ科目に同じ問題文）、dup（同じ答え）、choice（選択肢の正解混入・重複・数）、field（t・d・x の空欄）、img（画像ファイルがない・索引に札がない・同じ写真を別の札で使い回し）。
- GitHub Actions（.github/workflows/anki-cards.yml）が PR と main で自動実行。失敗した PR はマージしない。
- 通してよい札は tools/check_allow.json に「規則:科目:答え」と理由を書く（理由が空ならエラー、もう引っかからない例外も消せとエラー）。正式名称の「百舌鳥・古市古墳群」などはここ。関門導入時に引っかかった既存の約140枚は「修正待ち」として載せてあり、直したら消す。
- `node apps/anki-taisen/tools/shoot_all.js [URL] [出力先]`: 公開版の全ジャンルを開き、最初の札の問題と答え合わせ（資料画像）を撮って index.html に並べる。画像が読めない・開けないジャンルがあれば失敗。撮った一覧は人が目で見る。
- 画像の中身が札と合っているか（取り違え）は機械では判定しない（AIで見ると毎回トークンを食う）。取得時の一覧シートでの目視と、shoot_all の一覧で確認する。

### 2.0.2 4択の選択肢（2026-11-23 Keita「4択の選択肢がひどいものが多い（全くまよう余地がない）。ちゃんとやってください」）
- 誤答の選び方（src.html の pickDistractors）: 出題中の20枚からではなく、同じジャンルの全札から点数の高い順に3つ選ぶ。点数＝同じまとまり(g)+3、関連語(r)+2、相手の関連語に入っている+1、同じ字種（カタカナ語／漢字語／英字）+2、同じ語尾（〜法・〜説・〜主義・〜効果など）+2、長さが近い+1、同じ難易度+0.5。別解や、問題文に出ている語は選ばない。毎回同じにならないよう少し揺らす。
- それでもジャンル内に紛らわしい札が足りない札は、札に `dw`（誤答3つ）を手で書く。dw は4択のときだけ使い、入力で答えるモードには影響しない（数学などの `w` は選択式専用で入力モードが出なくなるので、用語の札には使わない）。dw は生成元（concepts/*.json）に書く。
- 関門の weak 規則: dw のない札で、誤答候補の3番目が4点未満なら失敗（同じまとまりも同じ字種もない＝迷う余地がない）。点数は字面しか見ないので、人物の札に本の名前が並ぶような意味のずれは拾えない。
- 札を作ったら `python3 apps/anki-taisen/tools/check_cards.py --choices 科目` で全札の誤答候補を一覧にし、全部読む。「人物には人物」「祭りには祭り」のように同じ種類の語が3つ並んでいなければ dw を書く。
- 2026-11-23: 候補が足りなかった146枚（キリスト教の教派、ユダヤ教の祭り、世界遺産（日本）、名著の人物など）に dw を書いた。
- 2026-11-23 基礎の全札見直し（Keita「あとで基礎全札選択肢みなおししといて」）: 基礎（lv1）約2,550枚の誤答候補を一覧で全部読み、種類がそろっていない1,030枚に dw を書いた（例: 作曲家の札に曲名、人物の札に書名、建物の札に別の時代・用途の建物が混じっていたもの）。時事問題は毎月入れ替わるので対象外。

## 2.0.3 トピックで選ぶ（2026-11-24 Keita「難易度って分類やめよう。トピックに変更」「情報科学は…ネットワークなどのトピックにわける」）
- 学問・教養・名著・時事の札のジャンル（数学・簿記3級・和文英訳も、2026-11-24 から）は、ロビーで難易度ではなくトピックを選ぶ。見出しは「トピック（出題数）」。トピック＝札のまとまり（g）。先頭に「ぜんぶ」。例: 情報科学＝情報の基礎・コンピュータのしくみ・アルゴリズム・データ構造とプログラミング・ネットワーク・セキュリティ・データベース・AI・ニューラルネットワーク・大規模言語モデル（LLM）・計算理論と情報社会の10個。
- 並びは札の中で最初に出てくる順（生成元の並び）。札が30枚未満のジャンル（名著の5冊）は「ぜんぶ」だけ。4枚未満のまとまりが2つ以上あれば「そのほか」に束ね、1つだけならその名前のまま出す（例: 法学の労働法2枚）。
- 仕組み（src.html の isTop・topicsOf・inTopic・okLv）: S.lv にトピック名（文字列、nb-lv にも文字で保存）が入り、3が「ぜんぶ」。対戦の待ち合わせ・開始でもトピック名を受け付ける（okLv）。札の読み込み前は選んだトピックを消さない。
- 歴史・鳥・木は従来の難易度のまま。
- 札を足すときは g を必ず付ける（関門 check_cards.py の field 規則で、g が空の札は止まる）。トピックが極端に少なくならないよう既存のまとまりに入れる。

  2. 何が変わった？（結果・意味。例: 活版印刷で本が安くなり、新しい考えが一気に広まった）
  3. 似た流れは？（時代や地域をこえた型。例: 秦→漢 と 隋→唐）

- 要点の書き方: 問いにまっすぐ答える一文。補足には具体例（人・数・その後）を入れ、要点のくり返しにしない。人名・用語・年を当てる問いは作らない（問いは なぜ／何が変わった／似た流れ／日本と世界のつながり の4種）。

## 2.0.6 難読語のふりがな（2026-11-24 Keita「漢字むずいやつふりがな振ってくれよ。カラーコーディネーターの色名とかに典型的だけど」）
- 読みにくい漢字の語に、ルビ（ruby 要素）でふりがなを振る。対象は全ジャンル（学問・教養・名著・時事・歴史の札）。
- 辞書は `src/ruby.tsv`（語<TAB>読み、見出しごとに分類）。`python3 apps/anki-taisen/src/build_ruby.py` で `data/ruby.json` を作る（送りがな入りの語は漢字の部分にだけ振る）。関門（check_cards.py の ruby 規則）が、書き方の誤りと ruby.json の作り直し忘れを止める。
- 選んだ語（2026-11-24 初版 約600語）: 常用漢字外の字を含む語と、熟字訓などふつうの音訓で読めない語のうち、大人でも読みに迷いそうなもの（例: 鴇色・浅葱・臙脂・黄櫨染、螺髪・白毫・忿怒、禊・祝詞・直会、五月雨・東風・野分、乙巳・口分田・白村江、日暮里・石神井・等々力）。天皇・奈良・味噌のように誰でも読める語は入れない。読みはすべて一語ずつ確かめた（形態素解析の読みは螺髪＝らはつ、楔形＝せっけい、六信＝むつのぶ など誤りが多いので使わない）。
- 読みが文脈で変わる語（八幡・秦・麻布・蛙・蜻蛉・銀杏・海神 など）は入れない。別の語の一部になる語は長い方を先に照合する。入れる前に、全札の文で前後が漢字に接している出現を一覧にして読み違いがないか確かめる（例: 「国後」は「帰国後」に当たるので「国後島」で登録、「明王」は「聖明王」を別に登録）。
- 振り方（src.html の addRuby）: 出題文・選択肢・答え・解説・関連・用語辞典・歴史の問いと答えに、段落ごとに最初の1回だけ振る。直後に（よみ）が書いてあれば振らない。
- 答え漏れ防止: 出題中の問題文では、読みが答え・別解（ひらがなにしたもの）と重なる語には振らない（例: 日本語「読み間違えやすい語」の「『出納』と書く」）。選択肢は正解だけ振らないと目印になるので、全部に同じ規則で振る。
- 足りない語・読みの誤りは、src/ruby.tsv に1行足して build_ruby.py を回す。
