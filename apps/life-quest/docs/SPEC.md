# 人生クエスト — 現行仕様

更新日: 2026-09-27

## 1. 目的

人生クエストは、自分が何を理解しているか、次に何を学べるかを可視化し、現実世界で学ぶ動機を生む個人向け学習ステータスシステムである。

人生クエスト自体がすべての教材を抱え込むことは目的にしない。本、Wikipedia、論文、動画、人との会話、現地体験など、現実世界の外部リソースへ出て学び、その結果を人生クエストへ持ち帰る。

基本ループ:

1. 人生クエストで学ぶ対象を見つける
2. 外部へ出て学ぶ
3. 理解できたトピックをMASTERする
4. ★・Lv・NEXTが更新される
5. 次の学習対象を見つける

人生クエストは「安全基地」「ステータス画面」「指針」「メンター」の役割を担う。

## 2. ステータス構造

基本階層は以下のみとする（2026-09-27 Keita決定。`IDEAS.md` §3・§4）。

`ステータス -> 分野 -> トピック`

- 上位単位の名称は「ステータス」。学問だけでなく資産・筋力などもステータスとして扱う。
- 各利用者は自分のステータス一覧を持つ。ステータスは「プリセットを追加」するか「自分で作る」。
- 自分で作ったステータスには、分野・トピックを自由に追加・編集・削除できる。プリセットのステータスにも自分の分野・トピックを追加できる（プリセット側の分野・トピックは編集しない）。
- トピックは十分に小さい学習単位とする。
- 学習順序は強制しない。

### トピックの種類

- **チェック型**: MASTER / 未MASTERを切り替える。1 MASTER = ★1。難易度や学習時間で★の重みは変えない。MASTER解除時は★1を減算する。
- **入力型**: 数値を記録する（例: 握力 kg、総資産 円）。単位を持てる。記録は履歴として残し、最新値を表示する。★・Lvには含めない。
  - 単位が「円」「万円」の値は `1,000,000 YEN` 表記で出す（万円は円に換算。言語設定に関係なくYEN）。
  - チェック項目が無く入力型だけのステータス（資産など）は、ステータス一覧と画面ヘッダーで★の代わりに最新の値を出す（記録が無ければ `—`）。

### ステータス★

ステータス★ = そのステータスでMASTER済みのチェック型トピック数（プリセットのトピック + 自分で追加したトピック）。

### プレイヤーLv

プレイヤーLv = MASTER済みチェック型トピックの総数（プリセット + 自分で追加したトピック）。

Lvとステータス★は保存値にせず、MASTERデータから算出する。

## 3. NEXT

NEXTは推薦であり、必修順序ではない。

候補は原則として次の優先順位で決める。

1. 未MASTER
2. 前提トピックを満たす
3. 重要度が高い
4. 推奨順序が早い

利用者はNEXTを無視して別のトピックを先にMASTERしてよい。

NEXTの候補はチェック型トピックのみ。自分で追加したトピックは前提・重要度を持たないため、前提を満たす扱い・重要度は標準（2）として並び順で選ぶ。チェック型トピックがないステータスではNEXT / COMPLETEを表示しない。

## 4. プリセット

プリセットは、DB側で用意したステータスの雛形（`quest_subjects` 配下の分野・トピック）。利用者はプリセットを1つずつ、またはまとまりごとに自分のステータス一覧へ追加できる。

プリセットは単独でもまとまり（`preset_group`）でも持てる。筋力・語学なども、それぞれ独立したプリセットとして追加していく。

### 単独プリセット

2026-09-27 Keita依頼で追加（たたき台）。どのまとまりにも属さない。

- **英語** 🔤: 主要な英語試験の得点・級を区切りごとのチェック型トピックにする（入力しなくてよく、レベル感が分かる）。分野は TOEIC L&R（400〜950点を50点刻み＋990点）、英検（3級〜1級）、TOEFL iBT（60〜110点を10点刻み）、IELTS（5.0〜8.0を0.5刻み）。
- **筋力** 💪: 分かりやすい指標の区切りをチェック型トピックにする。分野はベンチプレス・スクワット・デッドリフト（1回挙上の重量）、懸垂・腕立て伏せ（連続回数）、握力。
- **資産** 💰: 分野「総資産」に入力型トピック「総資産」（単位: 万円）ひとつ。手入力で記録し、銀行口座などとは連動しない（2026-09-27 Keita依頼）。★・Lvには数えない。

同じ分野内では一つ下の区切りを前提にしているので、NEXTは次の区切りを指す。中身は `CURRICULUM.md` と `/shared-world-core/supabase/seeds/006_english_strength_presets.sql`。

## 6. ステータス一覧UI

タブ名は「ステータス」。

基本表示例:

`01  [アイコン]  数学  Math  ★9`

その下に:

`NEXT ○○`（全トピックMASTER済みなら `COMPLETE`）

左端の2桁番号は行番号風の飾り（並び順）。★0のステータスは★を暗く表示する。

要件:

- 自分のステータス一覧のうち、非表示にしていないものを並び順で表示する。
- 並び順は行を長押し（約0.45秒）してドラッグで変えられる。指が画面の上下端に来たら自動でスクロールする。離した時点の順で `quest_user_statuses.sort_order` を10刻みに振り直して保存する。一覧の下に「長押しでドラッグして並べ替え」と小さく出す（2026-09-27 Keita依頼）。
- プリセットを選んだとき（初回セットアップ・まとめて追加）は 資産 → 筋力 → 英語 → 29学問 の順で一覧の末尾に加える（29学問の中は `quest_subjects.sort_order` 順）。`quest_subjects.sort_order` 自体は変えない（旧データ移行が学問の並び順の番号に依存しているため）。既存の一覧の順はそのまま。
- 名前の左にアイコンを表示する。プリセット（29学問・英語・筋力・資産）は16x16のドット絵アイコン `icons/<subject_id>.svg`、ドット絵の無いプリセットは `quest_subjects.icon` の絵文字、自作ステータスは利用者が入力した絵文字を使う（2026-09-27 Keita決定。`IDEAS.md` §7）。プリセット追加画面・初回セットアップの選択肢も同じアイコン。
- 一覧の最後に「＋ ステータスを追加」を置く。追加画面では、まだ一覧にないプリセット（まとまりは「まとめて追加」可）と、自作（アイコン・名前・英語名（任意））を選べる。
- 後から追加したステータスは一覧の最後に並ぶ。
- 旧画像アイコン（29学問スプライト `subjects.webp`、歴史学 `history.png`）は撤去済み。ドット絵アイコンはSVG（Dracula寄りの色、輪郭線なし）で、テーマを変えても同じ色。
- 日本語名の隣に薄い英語名。表示言語が English のときは英語名を主にし、日本語名を薄く出す（英語名の無い自作ステータスは日本語名のみ）。
- ★数は名前から離しすぎず、同一情報グループとして表示。
- パーセント進捗は表示しない。
- 不要な説明文を勝手に追加しない。

## 7. トピックUI

- 各ステータスのトピックは分野単位でまとめる。
- 分野見出しをタップすると配下のトピックを開閉できる。
- ステータス画面を開いた初期状態では全分野を閉じる。
- 分野見出しには `MASTER済みトピック数/総トピック数` を表示する。例: `数と計算 12/20`。
- トピックの並び順は既存の推奨順序を維持する。
- チェック型トピックはチェックでMASTER / 未MASTERを切り替える。
- 入力型トピックは右側に最新値と単位を表示する（未記録は `—`）。タップすると数値入力と直近5件の記録を表示し、「記録」で履歴に追加する。
- 分野見出しの `MASTER済み/総数` はチェック型トピックだけで数える。チェック型がない分野では表示しない。
- MASTERした瞬間、トピック右側に `MASTER!` を表示する。
- MASTER解除時に `MASTER!` も即時削除する。
- 各トピック右側に `★1` は表示しない。
- 出典は補助情報として小さく表示する。
- トピック数が多いステータスでは検索を提供する。日本語名・英語名のどちらでも引ける。
- 分野名・トピック名は日英併記。表示言語の側を主に、もう一方を下に小さく薄く出す（日本語なら「数と計算」の下に Numbers and Calculation、English なら逆）。英語名の無い分野・トピックは日本語名だけ（2026-09-27 Keita依頼）。

### 編集

ステータス画面の「編集」で編集モードに入り、「完了」で戻る。編集モードでは:

- 「ステータスを編集」: 自作ステータスは名前・英語名・アイコンの変更と削除（確認あり。配下の分野・トピック・記録も消える）。プリセットは「非表示にする」（MASTERは残り、追加画面から再表示できる）。
- 「＋ 分野を追加」
- 「＋ 分野を追加」「分野を編集」は分野名と英語の分野名（任意）。
- 自分で追加した分野に「＋ トピックを追加」（名前、英語のトピック名（任意）、種類: チェック / 入力、入力型は単位）と「分野を編集」（名前変更・削除）。
- 自分で追加したトピックをタップすると名前・英語名・単位の変更と削除。種類は作成後に変更しない。

フォントは §16 デザイン を参照。

## 8. プレイヤー表示・種族

ステータス一覧のプレイヤー窓に `Lv {master_count}`、`{display_name}`、称号を表示する（配置は §16）。

名前は変更可能。表示名は共通 `profiles.display_name` を使用し、人生クエストと「午後三時、夏の果て」で共有する。

共通キャラクターは `profiles.race_id` で決まる。

- 利用者が選ぶのは種族のみ。
- 同じ種族は全利用者で同一の見た目を使用する。
- 個別の髪型、服、顔、色等のアバターカスタマイズは持たない。
- 種族固有の見た目・描画倍率・移動速度は `races` マスタ側で管理する。

種族の選択・変更は夏の果て側で行う。人生クエストでは種族を選ばせず、設定にも出さない（2026-10-02 Keita依頼）。

## 10. 設定

設定画面では以下を扱う。

- テーマ変更（§16）
- 言語（日本語 / English）
- NEWSPAPERの言語（English / 日本語）
- ログアウト
- 全ステータスをリセット
- 全データをリセット

「言語」は画面の文言（タブ・ボタン・見出し・確認メッセージ・称号・状態名・テーマ名・種族名・ステータス名など）を日本語と英語で切り替える。初期値は日本語。分野名・トピック名は日英併記で、言語の側を主に表示する（§7）。出典など日本語しか無い中身は切り替えない。「NEWSPAPERの言語」はNEWSPAPERの記事のメイン表示の言語で、画面の言語とは別に選ぶ（初期値は English、§14）。どちらも端末ごとに `localStorage`（`lifeQuestLang`、`lifeQuestNewsLang`）に保存する（2026-09-27 Keita依頼）。翻訳は `i18n.js`。

「全ステータスをリセット」（2026-09-27に「全チェックをリセット」から名称変更、Keita依頼）は自分の `quest_topic_mastery` を全削除し、自分で追加したチェック型トピックのMASTERも解除する。入力型の記録、ステータス一覧、分野・トピックは残す。Lv / ★ / MASTER! はMASTERデータから再計算され、display_nameとrace_idは保持する。

「全データをリセット」は自分の人生クエストのデータ（`quest_topic_mastery`、`quest_topic_values`、`quest_user_statuses` とそれに付く自作の分野・トピック、`quest_user_settings`）を全削除し、初回のプリセット選択画面（§6）からやり直す。プリセット選択を終えるまでは、ステータスタブを押してもプリセット選択画面になる。display_name・race_id・状態は夏の果てと共通なので残す（2026-09-27 Keita依頼）。

どちらも実行前に「本当にデータを消しますか？」の確認を2回出し、両方OKしたときだけ消す（2026-09-27 Keita依頼）。

## 11. 認証・同期

人生クエストと「午後三時、夏の果て」は同じSupabaseプロジェクト `shared-world-core` を利用する。

- Supabase project ref: `rjydvhpqfhmlvpsykwzf`
- 認証: Supabase Auth
- 共通識別子: `auth.users.id` (UUID)
- パスワードはアプリ独自DBへ保存しない
- プロフィール・種族・Presenceを共通化する
- 人生クエストのMASTER状態は `quest_topic_mastery` へ保存する
- PC・スマホ等で同じアカウントへログインすれば同じMASTER状態を読み込む

### メール / パスワード

Web版にログイン・新規登録UIを実装する。

- 新規登録: `supabase.auth.signUp`
- ログイン: `supabase.auth.signInWithPassword`
- セッションはSupabase JSでブラウザに永続化・自動更新する
- 起動時の読み込みは、プロフィール・共通カリキュラム・自分のステータスを並列に取得する。1000件を超える表は1ページ目で件数を取り、残りを並列取得する
- 同じユーザーの `SIGNED_IN`（起動時・タブ復帰時にSupabase JSが出す）では全体を読み直さない
- Supabase Hosted Authのメール確認を利用する

### Google OAuth

Googleログインは有効（`app.js` の `GOOGLE_AUTH_ENABLED = true`）。Google Cloud OAuth ClientとSupabase Google Providerは設定済み。

ログイン画面のボタンは「Googleで続ける」に公式のGロゴ（4色）を添える。

同じSupabase AuthユーザーへGoogle identityを紐づける。Supabase Authの同一確認済みメールによるidentity linkingを利用できる。

当面は各アプリで一度ずつログインしてよい。将来、同一ドメイン配下または専用認証ドメインによるSSOを検討する。

## 12. 旧ブラウザデータ移行

旧Web版は `lifeQuestMathV06Public` にMASTER状態と名前をlocalStorage保存していた。

ログイン版では、各ユーザーにつき最初のログイン時に旧データが存在すればクラウド移行を選択できる。

- 数学の旧インデックスを安定したDB `topic_id` へ変換する。
- 他28学問の旧3仮トピックも対応するDBトピックへ変換する。
- MASTERは `quest_topic_mastery` へupsertする。
- クラウド側表示名が初期値「名無し」の場合のみ旧表示名を移行する。
- 移行後の正本はSupabaseとする。

localStorageは旧データ移行元としてのみ残し、新規MASTERの正本には使用しない。

## 14. NEWSPAPER

旧「デイリー」機構は廃止し、人生クエスト内の正式タブを `NEWSPAPER` とする。独立した製品版デイリーWebページは持たない。

NEWSPAPERの紙面はテーマに関係なく生成り地に茶系の文字のシックな配色とし（枠だけテーマ色。2026-09-27 Keita選択のG案）、フォントはBBC Newsに寄せて、英語見出し `Source Serif 4`、英語本文 `Noto Sans`、日本語 `Noto Sans JP` を使う（2026-09-27 Keita依頼）。文字は一回り大きめにし、幅600px以上（PCなど）では本文と見出しをもう一段大きくする（2026-09-27 Keita依頼）（§16 の等幅フォントは使わない）。

1. NEWS
2. MARKETS

4. DAILY QUIZ

### データ取得

人生クエスト側はコンテンツを生成せず、外部生成された公開JSONを表示する。

- データrepo: `keisasaki3/life-quest-newspaper-data`
- Base URL: `https://raw.githubusercontent.com/keisasaki3/life-quest-newspaper-data/main/`
- 最初に `newspaper/latest.json` を取得する。
- `latest.json` の `path` が示す日付JSONを次に取得する。
- 毎朝6:15 JSTまでにデータ生成側で更新する。生成はClaudeのroutineが `life-quest-newspaper-data` の `GENERATE.md` に従って行う（2026-09-27 ChatGPTから移行）。
- `latest.json` と日付JSONの取得ではキャッシュを避ける。
- 通信失敗時は架空・サンプル教材へフォールバックせず、エラー表示と再試行のみ提供する。
- `life-quest-newspaper-data` の簡易Webビューは開発・確認用であり、人生クエスト本体の正式NEWSPAPER画面ではない。

### NEWS

NEWSをNEWSPAPERの主役とする。

- 英語をメインに読ませる（2026-09-27 Keita決定）。設定の「NEWSPAPERの言語」を日本語にすると、日本語見出し・日本語summaryがメインになり、英語は記事ごとの「English」ボタンで開閉する（2026-09-27 Keita依頼。§10）。
- 記事はカードにせず、古い新聞のように二重線で区切る。見出しの上に通し番号と region を小さく出し、見出しの下に細い茶色の区切り線を入れる（2026-09-27 Keita選択）。
- region は文字に絵文字アイコンを添える（例: 🌍 WORLD、🇯🇵 JAPAN。未知の region は 🌐）。
- 見出し: `headline_en` があれば英語見出しを表示する。`headline_en` がなければ日本語 `headline` を見出しにする。
- 一覧では英語summaryを1文ごとに1行空けて表示し（日本語も同じ。BBC風。2026-09-27 Keita依頼）、その下に主な出典（`sources[0]`）をリンクで出す。訳（日本語。NEWSPAPERの言語が日本語なら英語）は記事ごとの「日本語」（または「English」）ボタンで開閉し、初期状態は閉じる。開くと、見出しと各文の真下にその文の訳が出る（2026-09-27 Keita依頼）。
- 日本語summaryと英語summaryはセンテンス単位で対応させる。
- 記事の書き方は life-quest-newspaper-data の `STYLE.md` に従う（ひとこと見出し＋事実とAIの解説で2〜3文＋出典。2026-09-27 Keita決定）。解説はsummaryの最後の文として書き、別のコメント欄は作らない。
- BACKGROUND / WHY IT MATTERS / 2つ目以降のSOURCES は記事ごとの「詳細を見る」で開閉する。どれも無い記事には「詳細を見る」を出さない。
- SOURCESは外部リンクとして開けるようにする。

## 17. 日課

2026-10-02 Keita依頼。毎日やることを登録してチェックし、一日の結果をGoogleカレンダーに残す。下タブと見出しは「日課🔥」（`routine-ui.js` / `routine.css`）。

- 日課は全部チェック型。目標（30分など）は名前に自分で書く。やる曜日を選べる（初期値は毎日）。
- 日課ごとにアイコンを決まった25種（📘📖✍️🗣️💪🏃🧘🚶😴💧🥗🧹💰🎸🎨🤝👥🏙️🌆🌇🌃🌉🧳🌐🌱。🤝は人と会う・婚活など、`routine-ui.js` の `ROUTINE_ICONS`）から選ぶ。色はアイコンごとに固定で保存しない。任意の一言メモを付けられる（2026-10-02 Keita依頼）。
- 日課の行: アイコン（その色の枠。チェックすると塗る）、名前、メモ、表示中の日までの7日のマス（やる曜日でない日は枠だけ）、その日課の連続日数「📚N」（やる曜日だけ数え、今日がまだなら昨日から）、チェック欄。
- 日付はJST 0時切替。◀ ▶ で過去の日に戻ってチェック・記録できる（今日より先へは進めない）。
- 日付の下に日替わりの金言（今努力すると人生がよくなる、に関わる言葉）を「金言」と「― 言った人」で出す。表示中の日付で決まり、一覧は `routine-ui.js` の `ROUTINE_QUOTES`（出典がはっきりした22個、日英）。日付は大きく出す（金言の上、2026-10-02 Keita依頼で入れ替え）。達成数（3/5 など）は出さない（2026-10-02 Keita依頼）。
- 表示: 連続日数（その日の日課を全部やった日の連続。日課の無い日は飛ばし、今日が途中なら昨日から数える）、直近7日・30日の達成率、直近28日のマス。
- 締めボタンの下の「日課を編集」で編集画面に入り（戻るのは右上の「完了」）、追加・名前と曜日の変更・削除・長押しドラッグの並べ替え。削除は `archived_at` を入れるだけで、過去のチェックと達成率は残る。
- ★・プレイヤーLvとはつなげない。「全データをリセット」「全ステータスをリセット」の対象外。

### Googleカレンダー

- 正本はSupabase。カレンダーは見るための写し。
- 許可（1時間有効）は端末の `localStorage`（`lifeQuestCalendarToken`）に保存し、開き直しても1時間はポップアップを出さない。ログアウトで消す。
- 「この日を締めてカレンダーに記録」で、ブラウザからGoogleの許可（Google Identity Services のトークン）を取り、アプリが作った専用カレンダー「人生クエスト 日課」に終日予定を1件書く。権限は `calendar.app.created`（アプリが作ったカレンダーだけ。普段の予定は触らない）。ログイン方法（メール / Google）に関係なく使える。
- 予定: タイトル `日課 4/5 ✅✅⬜✅✅`、説明は日課ごとの ✓ / ✗ とアイコン。色は全部=緑、半分以上=黄、それ未満=赤。
- 予定IDは日付から決める（`lq20261002`）。押し直すと同じ予定を上書きし、重複しない。
- 専用カレンダーのIDは `quest_routine_settings.calendar_id` に持つ。消されていたら作り直す。
- Google Cloud 側: Calendar API を有効化し、OAuthクライアント（Supabaseログインと同じ）の「承認済みのJavaScript生成元」に本番URLを入れ、同意画面に `calendar.app.created` を追加する。
