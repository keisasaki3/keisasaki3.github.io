# 人生クエスト — 現行仕様

更新日: 2026-09-27

## 1. 目的

人生クエストは、自分が何を理解しているか、次に何を学べるかを可視化し、現実世界で学ぶ動機を生む個人向け学習ステータスシステムである。

人生クエスト自体がすべての教材を抱え込むことは目的にしない。本、Wikipedia、論文、動画、人との会話、現地体験など、現実世界の外部リソースへ出て学び、その結果を人生クエストへ持ち帰る。

基本ループ:

1. 人生クエストで学ぶ対象を見つける
2. 外部へ出て学ぶ
3. 理解できたトピックをMASTERする
4. ★・Lv・NEXTが更新される
5. 次の学習対象を見つける

人生クエストは「安全基地」「ステータス画面」「指針」「メンター」の役割を担う。

## 2. ステータス構造

基本階層は以下のみとする（2026-09-27 Keita決定。`IDEAS.md` §3・§4）。

`ステータス -> 分野 -> トピック`

- 上位単位の名称は「ステータス」。学問だけでなく資産・筋力などもステータスとして扱う。
- 各利用者は自分のステータス一覧を持つ。ステータスは「プリセットを追加」するか「自分で作る」。
- 自分で作ったステータスには、分野・トピックを自由に追加・編集・削除できる。プリセットのステータスにも自分の分野・トピックを追加できる（プリセット側の分野・トピックは編集しない）。
- トピックは十分に小さい学習単位とする。
- 学習順序は強制しない。

### トピックの種類

- **チェック型**: MASTER / 未MASTERを切り替える。1 MASTER = ★1。難易度や学習時間で★の重みは変えない。MASTER解除時は★1を減算する。
- **入力型**: 数値を記録する（例: 握力 kg、総資産 円）。単位を持てる。記録は履歴として残し、最新値を表示する。★・Lvには含めない。

### ステータス★

ステータス★ = そのステータスでMASTER済みのチェック型トピック数（プリセットのトピック + 自分で追加したトピック）。

### プレイヤーLv

プレイヤーLv = MASTER済みチェック型トピックの総数（プリセット + 自分で追加したトピック）。

Lvとステータス★は保存値にせず、MASTERデータから算出する。

## 3. NEXT

NEXTは推薦であり、必修順序ではない。

候補は原則として次の優先順位で決める。

1. 未MASTER
2. 前提トピックを満たす
3. 重要度が高い
4. 推奨順序が早い

利用者はNEXTを無視して別のトピックを先にMASTERしてよい。

NEXTの候補はチェック型トピックのみ。自分で追加したトピックは前提・重要度を持たないため、前提を満たす扱い・重要度は標準（2）として並び順で選ぶ。チェック型トピックがないステータスではNEXT / COMPLETEを表示しない。

## 4. プリセット

プリセットは、DB側で用意したステータスの雛形（`quest_subjects` 配下の分野・トピック）。利用者はプリセットを1つずつ、またはまとまりごとに自分のステータス一覧へ追加できる。

プリセットは単独でもまとまり（`preset_group`）でも持てる。筋力・語学なども、それぞれ独立したプリセットとして追加していく。

### 単独プリセット

2026-09-27 Keita依頼で追加（たたき台）。どのまとまりにも属さない。

- **英語** 🔤: 主要な英語試験の得点・級を区切りごとのチェック型トピックにする（入力しなくてよく、レベル感が分かる）。分野は TOEIC L&R（400〜950点を50点刻み＋990点）、英検（3級〜1級）、TOEFL iBT（60〜110点を10点刻み）、IELTS（5.0〜8.0を0.5刻み）。
- **筋力** 💪: 分かりやすい指標の区切りをチェック型トピックにする。分野はベンチプレス・スクワット・デッドリフト（1回挙上の重量）、懸垂・腕立て伏せ（連続回数）、握力。

同じ分野内では一つ下の区切りを前提にしているので、NEXTは次の区切りを指す。中身は `CURRICULUM.md` と `/shared-world-core/supabase/seeds/006_english_strength_presets.sql`。

## 5. カリキュラム方針

標準プリセットは大学一般教養から学部基礎程度までを目安とする。

ただし現在のカリキュラム整備では、まず日本の学習指導要領を基準に学校教育範囲を漏れなく地図化し、その後に大学教養・学問固有の重要領域を追加する。

数学は現在、小学算数・中学数学・高校数学をベースに20分野・275トピックをDBへ収録している。

数学以外の28学問は、旧Web版に存在した各3件の仮トピックをクラウド同期移行用としてDBへ残している。今後、本カリキュラムへ置換する。

出典表記は以下を使用する。

- 小学算数
- 中学数学
- 小学算数・中学数学
- 高校 数学I / II / III / A / B / C 等

## 6. ステータス一覧UI

タブ名は「ステータス」。

基本表示例:

`01  [アイコン]  数学  Math  ★9`

その下に:

`NEXT ○○`（全トピックMASTER済みなら `COMPLETE`）

左端の2桁番号は行番号風の飾り（並び順）。★0のステータスは★を暗く表示する。

要件:

- 自分のステータス一覧のうち、非表示にしていないものを並び順で表示する。
- 名前の左にアイコンを表示する。プリセットは `quest_subjects.icon` の絵文字、自作ステータスは利用者が入力した絵文字を使う（2026-09-27 Keita決定。`IDEAS.md` §7）。
- 一覧の最後に「＋ ステータスを追加」を置く。追加画面では、まだ一覧にないプリセット（まとまりは「まとめて追加」可）と、自作（アイコン・名前・英語名（任意））を選べる。
- 後から追加したステータスは一覧の最後に並ぶ。
- 旧画像アイコン（29学問スプライト `subjects.webp`、歴史学 `history.png`）は撤去済み。
- 日本語名の隣に薄い英語名。
- ★数は名前から離しすぎず、同一情報グループとして表示。
- パーセント進捗は表示しない。
- 不要な説明文を勝手に追加しない。

## 7. トピックUI

- 各ステータスのトピックは分野単位でまとめる。
- 分野見出しをタップすると配下のトピックを開閉できる。
- ステータス画面を開いた初期状態では全分野を閉じる。
- 分野見出しには `MASTER済みトピック数/総トピック数` を表示する。例: `数と計算 12/20`。
- トピックの並び順は既存の推奨順序を維持する。
- チェック型トピックはチェックでMASTER / 未MASTERを切り替える。
- 入力型トピックは右側に最新値と単位を表示する（未記録は `—`）。タップすると数値入力と直近5件の記録を表示し、「記録」で履歴に追加する。
- 分野見出しの `MASTER済み/総数` はチェック型トピックだけで数える。チェック型がない分野では表示しない。
- MASTERした瞬間、トピック右側に `MASTER!` を表示する。
- MASTER解除時に `MASTER!` も即時削除する。
- 各トピック右側に `★1` は表示しない。
- 出典は補助情報として小さく表示する。
- トピック数が多いステータスでは検索を提供する。

### 編集

ステータス画面の「編集」で編集モードに入り、「完了」で戻る。編集モードでは:

- 「ステータスを編集」: 自作ステータスは名前・英語名・アイコンの変更と削除（確認あり。配下の分野・トピック・記録も消える）。プリセットは「非表示にする」（MASTERは残り、追加画面から再表示できる）。
- 「＋ 分野を追加」
- 自分で追加した分野に「＋ トピックを追加」（名前、種類: チェック / 入力、入力型は単位）と「分野を編集」（名前変更・削除）。
- 自分で追加したトピックをタップすると名前・単位の変更と削除。種類は作成後に変更しない。

フォントは §16 デザイン を参照。

## 8. プレイヤー表示・種族

ステータス一覧のプレイヤー窓に `Lv {master_count}`、`{display_name}`、称号を表示する（配置は §16）。

名前は変更可能。表示名は共通 `profiles.display_name` を使用し、人生クエストと「午後三時、夏の果て」で共有する。

共通キャラクターは `profiles.race_id` で決まる。

- 利用者が選ぶのは種族のみ。
- 同じ種族は全利用者で同一の見た目を使用する。
- 個別の髪型、服、顔、色等のアバターカスタマイズは持たない。
- 種族固有の見た目・描画倍率・移動速度は `races` マスタ側で管理する。

初回ログイン後、`race_id` が未設定なら種族選択を要求する。

### 初回セットアップ

人生クエストの初回セットアップ未完了（`quest_user_settings.setup_completed_at` が空）の利用者には、最初に「プリセットを選ぶ」画面を出す（2026-09-27 Keita決定）。

- まとまり（29学問）ごとの「すべて」チェックと、プリセット個別のチェック。
- 「はじめる」で選んだプリセットを追加し、セットアップ完了にする。何も選ばずに始めてもよい。
- migration 005 適用時点の既存アカウントは、29学問をすべて追加済み・セットアップ完了として引き継ぐ。

## 9. 共通の状態

以下の状態を `player_presence` で共有する（上位単位の「ステータス」と区別するため、画面上の名称は「状態」。2026-09-27 Keita決定）。

- online: オンライン
- studying: 勉強中
- reading: 読書中
- busy: 取り込み中
- afk: AFK

人生クエスト設定画面から自分の状態を変更できる。

## 10. 設定

設定画面では以下を扱う。

- 種族変更
- 状態変更
- テーマ変更（§16）
- ログアウト
- 全チェックをリセット

「全チェックをリセット」は自分の `quest_topic_mastery` を全削除し、自分で追加したチェック型トピックのMASTERも解除する。入力型の記録、ステータス一覧、分野・トピックは残す。Lv / ★ / MASTER! はMASTERデータから再計算され、display_nameとrace_idは保持する。実行前に確認を出す。

## 11. 認証・同期

人生クエストと「午後三時、夏の果て」は同じSupabaseプロジェクト `shared-world-core` を利用する。

- Supabase project ref: `rjydvhpqfhmlvpsykwzf`
- 認証: Supabase Auth
- 共通識別子: `auth.users.id` (UUID)

### メール / パスワード

- Supabase Hosted Authのメール確認を利用する

当面は各アプリで一度ずつログインしてよい。将来、同一ドメイン配下または専用認証ドメインによるSSOを検討する。

## 12. 旧ブラウザデータ移行

旧Web版は `lifeQuestMathV06Public` にMASTER状態と名前をlocalStorage保存していた。

ログイン版では、各ユーザーにつき最初のログイン時に旧データが存在すればクラウド移行を選択できる。

- 数学の旧インデックスを安定したDB `topic_id` へ変換する。
- 他28学問の旧3仮トピックも対応するDBトピックへ変換する。
- MASTERは `quest_topic_mastery` へupsertする。
- クラウド側表示名が初期値「名無し」の場合のみ旧表示名を移行する。
- 移行後の正本はSupabaseとする。

localStorageは旧データ移行元としてのみ残し、新規MASTERの正本には使用しない。

## 14. NEWSPAPER

旧「デイリー」機構は廃止し、人生クエスト内の正式タブを `NEWSPAPER` とする。独立した製品版デイリーWebページは持たない。

NEWSPAPERの紙面はテーマに関係なく白地に黒文字とし（枠だけテーマ色）、本文は英語 `Literata`、日本語 `Noto Sans JP` を使う（§16 の等幅フォントは使わない）。

表示順は以下で固定する。

1. NEWS
2. MARKETS
3. DAILY CULTURE
4. DAILY QUIZ

### データ取得

人生クエスト側はコンテンツを生成せず、外部生成された公開JSONを表示する。

- データrepo: `keisasaki3/life-quest-newspaper-data`
- Base URL: `https://raw.githubusercontent.com/keisasaki3/life-quest-newspaper-data/main/`
- 最初に `newspaper/latest.json` を取得する。
- `latest.json` の `path` が示す日付JSONを次に取得する。
- 毎朝6:15 JSTにデータ生成側で更新する。
- `latest.json` と日付JSONの取得ではキャッシュを避ける。
- 通信失敗時は架空・サンプル教材へフォールバックせず、エラー表示と再試行のみ提供する。
- `life-quest-newspaper-data` の簡易Webビューは開発・確認用であり、人生クエスト本体の正式NEWSPAPER画面ではない。

### NEWS

NEWSをNEWSPAPERの主役とする。

- 英語をメインに読ませる（2026-09-27 Keita決定）。
- 1記事1カード。カード上部の帯に通し番号と region を出し、記事の切れ目を明確にする。
- region は文字に絵文字アイコンを添える（例: 🌍 WORLD、🇯🇵 JAPAN。未知の region は 🌐）。
- 見出し: `headline_en` があれば英語見出しを表示する。`headline_en` がなければ日本語 `headline` を見出しにする。
- 一覧では英語summaryを表示する。日本語（`headline_en` がある日は日本語見出しも含む）は記事ごとの「日本語」ボタンで開閉し、初期状態は閉じる。
- 日本語summaryと英語summaryはセンテンス単位で対応させる。
- BACKGROUND / WHY IT MATTERS / SOURCES は記事ごとの「詳細を見る」で開閉する。
- SOURCESは外部リンクとして開けるようにする。

### MARKETS

- JSON内の市場カテゴリ配列を基本に描画し、UI側へ固定銘柄をハードコードしない。
- 各項目は symbol / value / unit / change_pct または change_bp を表示する。
- `market_moves` または互換キー `moves` が存在する場合は `MARKET MOVES` として表示する。

### DAILY CULTURE

旧デイリー教養を全面刷新した1日1本の読み物とする。

- title
- body
- EXPLORE

を表示し、bodyは全文読めるようにする。

### DAILY QUIZ

旧デイリーQUIZを全面刷新した1日1問のクイズとする。

- genre
- question
- 「答えを見る」

を初期表示し、answer / explanation / sources は開閉領域に入れる。選択肢形式にはしない。

### 廃止した旧デイリー要素

- 旧デイリー基礎学問
- 旧デイリーWORLD
- 旧教材の日付ローテーション
- 旧教材の既読・回答保存
- 旧教材からMASTERへの自動反映
- 旧サンプル教材・fixture・通信失敗時のサンプルフォールバック

DAILY CULTURE / DAILY QUIZ の重複防止registryはデータ生成側の責務とし、人生クエスト側は生成せず表示のみ担当する。
